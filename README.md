# GPT Image Playground

面向团队内部的 AI 图片生成、编辑与 Agent 工作台。项目把图片模型调用、参考图管理、局部编辑、历史记录和受控 Agent 执行整合在同一个 Web 界面中，适合从创意探索到结果复用的连续工作流。

项目支持 OpenAI、OpenAI-compatible API、fal.ai 和可导入的自定义 HTTP 服务商。生成记录、图片与常用配置默认保存在浏览器本地，便于个人持续迭代，也避免把工作历史集中上传到额外的数据服务。

## 应用场景

- **文本生成图片**：输入自然语言 Prompt，选择尺寸、质量和输出数量，快速生成候选素材。
- **参考图迭代**：上传或粘贴参考图，在保持主体、风格或构图的基础上继续修改。
- **局部遮罩编辑**：通过内置遮罩编辑器标记修改区域，再交给图片模型执行局部重绘。
- **多轮创意协作**：在 Chat Agent 中用对话描述目标，由 Agent 结合当前图片上下文组织后续操作。
- **受控任务执行**：Tool Agent 流式生成结构化计划，并在规划完成后自动调用受限工具，适合需要明确执行边界和可追踪过程的任务。
- **画布精修**：把结果送入 OpenShop 进行图层、排版和画布级编辑，并保存为新的历史记录。
- **素材管理与复用**：筛选、收藏、批量选择、下载和导出历史任务，把已有结果快速转为下一轮参考图。

## 核心能力

### 图片生成与编辑

- 支持 Images API 与 Responses API。
- 单次可使用多张参考图，并支持剪贴板粘贴和拖拽上传。
- 支持可视化遮罩编辑和图片预处理。
- 支持单次多图生成，以及将历史结果直接复用为参考图。
- 展示模型实际生效的尺寸、质量、耗时和改写后的 Prompt，便于对比请求参数与真实响应。

### Agent 工作台

- Chat Agent 适合开放式对话、需求澄清和连续创作。
- Tool Agent 采用“流式规划—自动执行”流程，计划生成完成且输入校验通过后立即开始图片操作。
- Tool Agent 的规划器不直接持有执行工具；执行器只能处理服务端冻结计划允许的操作。
- 支持流式展示 Agent 回复、计划、执行进度和结果。
- Tool Agent 可按运行环境能力使用 Web Search，为需要外部资料的规划补充上下文。

### OpenShop 画布

- 提供嵌入式画布编辑工作区。
- 支持从历史结果进入手动编辑，也支持 Tool Agent 调用受限的 `openshop.edit` 操作。
- 编辑结果以新历史记录保存，不覆盖原始图片。

### 配置与历史管理

- 支持多个 API Profile，并可切换服务商、模型和接口模式。
- 支持 OpenAI-compatible、fal.ai 与自定义同步或异步 HTTP Provider。
- 支持瀑布流历史、状态筛选、全屏预览、快捷下载和批量操作。
- 历史任务保存请求参数与实际响应参数，便于复现和比较。
- 支持将本地历史打包导出，便于备份或迁移。

## 工作模式


| 模式         | 适合任务                      | 操作方式                        | 主要边界                              |
| ---------- | ------------------------- | --------------------------- | --------------------------------- |
| Gallery    | 参数明确的直接生成、参考图编辑、历史管理      | 用户直接选择配置并提交                 | 使用当前 API Profile 或管理员提供的统一配置      |
| Chat Agent | 开放式沟通、多轮创作、由 Agent 组织图片任务 | 对话后由 Agent 调用可用的图片能力        | 可用模型和凭据取决于当前运行环境                  |
| Tool Agent | 需要限制工具权限和保留执行证据的任务        | Agent 流式规划，完成后自动执行          | 只能执行服务端冻结计划允许的操作；不可用时不会自动降级到 Chat |
| OpenShop   | 图层、排版和画布级精修               | 用户手动编辑，或由 Tool Agent 执行受限编辑 | 编辑结果另存为新历史，不替换原图                  |


Chat 与 Tool 是两项独立能力。某一种模式不可用或执行失败时，系统不会静默切换到另一种模式；用户应根据界面显示的能力状态选择可用路径。

## 典型使用流程

### 直接生成

1. 在 Gallery 选择 API Profile、模型和接口模式。
2. 输入 Prompt，并按需设置尺寸、质量和输出数量。
3. 添加参考图或遮罩。
4. 提交任务并在历史列表查看生成进度。
5. 下载结果，或将结果转为参考图继续迭代。

### 使用 Chat Agent

1. 进入 Agent 工作区并选择 Chat。
2. 用自然语言描述目标、约束和期望风格。
3. 在对话中补充参考图或继续调整要求。
4. 查看 Agent 返回的过程与图片结果。
5. 将满意结果下载、复用或送入 OpenShop 精修。

### 使用 Tool Agent

1. 进入 Agent 工作区并选择 Tool。
2. 描述任务，并附上必要的参考图。
3. 查看 Agent 流式返回的规划说明。
4. 规划完成且输入校验通过后，系统自动执行图片生成或编辑。
5. 查看执行详情与结果。计划过期、输入变化或自动执行中断时，需要重新规划。

### 使用 OpenShop

1. 从历史图片进入 OpenShop，或在 Tool Agent 任务中触发画布编辑。
2. 调整图层、构图、文字和画布内容。
3. 导出并保存结果。
4. 回到历史列表继续下载或作为参考图使用。

## 数据与隐私

- 浏览器端历史、图片和个人 API Profile 默认保存在 IndexedDB。
- 本地图片使用内容哈希去重，减少重复存储。
- 用户可导出本地历史用于备份；清理浏览器站点数据会移除未备份的本地记录。
- 使用个人 API Profile 时，图片、Prompt 和凭据会按所选 Provider 的调用方式发送给对应上游。
- 使用团队统一配置或 Tool Agent 时，浏览器不会获得服务端保存的上游 API Key。
- OpenShop 编辑在隔离的嵌入式页面中运行，保存时生成新的历史记录。

## 运行边界

- 本项目是图片工作台，不提供团队账号、角色权限、素材审批或共享资产库。
- Tool Agent 只有在 Agent Gateway 能力可用时才会开放；界面未提供该模式时，应使用 Gallery 或 Chat Agent。
- Tool Agent 的计划具有有效期并绑定输入；参考图、参数或任务上下文变化后不能继续复用旧计划。
- Tool Agent 执行失败时保持失败状态，不会使用 Chat、旧代理或浏览器配置继续执行。
- Tool Agent 的服务端执行器只接受其支持的图片结果格式；上游协议不兼容时任务会明确失败。
- Chat 与 Tool 的会话和任务状态彼此独立，切换模式不会把一方的执行权限转移给另一方。
- 浏览器本地数据不等同于团队备份；重要结果应主动下载或导出。
- 自定义 Provider 的字段映射和任务轮询逻辑由导入配置定义，使用前应确认其与目标 API 契约一致。

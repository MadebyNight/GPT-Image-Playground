# Agent 响应式消息流设计

日期：2026-08-12  
状态：已确认，实施计划已补充

## 1. 目标

将 Chat Agent 与 Tool Agent 统一为一套接近 ChatGPT 的响应式消息流界面，解决当前三栏工作台过于拥挤、结果图片按中央栏宽度放大、输入区遮挡内容以及两种 Agent 展示逻辑割裂的问题。

本次设计只调整展示层和布局状态，保留现有任务执行、历史持久化、Lightbox、图片编辑、OpenShop、Planner 与 Gateway 协议。

成功后的直接体验：

- 用户请求和 Agent 回复按时间顺序自然流动，不再嵌套完整任务详情卡。
- 生成结果默认只显示最大 `160×160px` 的缩略图，不裁切、不放大占满工作区。
- 点击缩略图继续使用现有 Lightbox。
- 缩略图下方继续显示现有高频操作，不增加重复入口或次级菜单。
- 左侧历史默认展开且可收起；右侧模板默认收起且可展开。
- Chat 与 Tool 共享同一布局、消息视觉和响应式行为。

## 2. 非目标

本次不包含：

- 修改 Gateway、Planner、Tool Agent API 或 OpenShop iframe 协议。
- 修改 `TaskRecord`、Agent 会话或本地 Run 的持久化结构。
- 新增图片查看、编辑、下载或历史操作能力。
- 重做画廊、任务详情弹窗、Lightbox 或遮罩编辑器。
- 改变任务提交、计划确认、取消执行、保存重试等业务流程。

## 3. 当前问题

### 3.1 结果图被当作主画布

Tool 模式在 `AgentMainWorkspace` 中直接渲染 `TaskDetailContent`。后者的图片舞台使用内容驱动高度，只有最小高度而没有 Agent 场景的预览上限。实测在 1874px 宽桌面中，800×800 结果图显示为 776×776px，占据中央工作区绝大部分首屏。

### 3.2 固定三栏压缩中央内容

桌面布局从 `xl` 断点开始同时常驻历史、中央工作区和模板栏。1366px 笔记本上中央列明显偏窄，固定在页面底部的输入区进一步遮挡可见内容。

### 3.3 Chat 与 Tool 展示逻辑分叉

Chat 已有轻量预览和折叠详情，Tool 仍复用完整任务详情。相同的图片结果、状态和操作在两种模式下具有不同的信息层级，后续维护容易继续分叉。

## 4. 设计原则

1. **消息优先**：结果是 Agent 回复的一部分，不是默认展开的编辑画布。
2. **复用现有能力**：Lightbox、操作按钮、任务详情和执行状态均复用现有逻辑。
3. **高频动作直达**：编辑、收藏、删除等现有高频动作始终显示，不隐藏到更多菜单。
4. **渐进披露**：错误摘要和恢复动作直接可见；技术详情、参数和原始响应按需展开。
5. **布局状态与业务状态隔离**：侧栏显隐不写入任务记录，不影响执行和历史选择。
6. **无数据迁移**：现有历史记录应直接以新消息流恢复展示。

## 5. 页面骨架

### 5.1 共享 Agent Shell

`AgentWorkspace` 继续作为 Agent 页面入口，但改为共享 Shell：

```text
AgentWorkspace
├── AgentModeSwitcher
├── AgentHistoryPanel / HistoryRail
├── AgentConversationStream
│   └── AgentComposer（复用 InputBar 业务逻辑）
└── AgentTemplateDrawer / TemplateRail
```

Chat 与 Tool 不再各自决定整页结构，只向 `AgentConversationStream` 提供各自的消息内容、执行状态和可用动作。

### 5.2 桌面布局

- `1280px` 及以上使用桌面侧栏布局。
- 左侧历史栏默认展开为 `240px`。
- 历史栏可收起为 `48px` 的窄入口；中央消息流自动占用释放出的宽度。
- 右侧模板默认只显示 `48px` 的入口栏。
- 点击模板入口后，以 `320px` 的覆盖式侧栏从右侧展开，不压缩中央消息流。
- 中央消息内容最大宽度为 `760px`，水平内边距使用 `clamp(16px, 5vw, 72px)` 随视口流式变化。
- 历史栏、对话流和模板栏分别滚动，互不带动。

### 5.3 输入区

现有 `InputBar` 保留提交、附件、参数、校验和快捷键逻辑，但增加 Agent 内嵌展示方式：

- Agent 模式下输入区位于中央列底部，不再依赖整页固定定位和猜测式列偏移。
- 消息滚动区与输入区分层，输入区不覆盖最后一条消息和操作按钮。
- 画廊继续使用现有全局固定输入区，不受本次调整影响。

### 5.4 中小屏与手机

- 低于 `1280px` 后，消息流占满可用宽度。
- 历史与模板均改为覆盖式抽屉，进入页面时默认关闭，避免遮挡内容。
- 抽屉带遮罩、焦点约束、关闭按钮，并支持 `Escape` 关闭。
- 缩略图最大值仍为 `160×160px`；极窄视口允许按容器等比缩小，不裁切。
- 操作行允许换行，保持触控目标尺寸，不改为横向溢出或更多菜单。

## 6. 布局偏好状态

新增的状态只描述界面布局：

- 桌面历史栏是否收起。
- 桌面模板栏是否展开。
- 当前移动端抽屉类型或关闭状态。

桌面偏好可通过现有安全存储方式或 `localStorage` 保存；首次使用默认历史展开、模板收起。移动端抽屉不持久化打开状态，每次进入或模式切换后保持关闭。

这些状态不进入 `TaskRecord`、Agent 会话、执行快照或 Gateway 请求。

## 7. 消息流结构

### 7.1 Chat

选中 Chat 会话后，按 `agentTurn` 和创建顺序渲染全部轮次：

1. 用户请求消息。
2. Agent 文本回复或流式文本。
3. 状态、图片结果、错误摘要和操作。

流式事件继续更新当前最后一轮，不因布局切换或 Chat/Tool 切换丢失。已有会话恢复时直接从现有任务记录派生消息，不新增持久化消息模型。

### 7.2 Tool

Tool 任务在同一消息位置经历完整生命周期：

1. 用户请求。
2. Planner 生成计划。
3. 等待用户确认或返回修改。
4. Gateway/OpenShop 执行与保存。
5. 完成结果或失败状态。

状态变化在原消息位置更新，完成后不切换到另一种页面结构。计划确认卡仍可保留必要的审查信息和操作，但其视觉归属于 Agent 回复流。

### 7.3 滚动行为

- 新消息或流式增量到达时，只有用户位于消息流底部附近才自动跟随。
- 用户主动向上阅读时不强制拉回底部，并提供轻量的“回到底部”入口。
- 选择历史记录后定位到该会话最新消息。
- 切换 Chat/Tool 时分别保留当前选中任务与各自滚动上下文；不卸载正在进行的 Chat 流。

## 8. Agent 回复与结果

### 8.1 文本和状态

- 用户消息右对齐，以简洁气泡展示。
- Agent 回复左对齐，以自然文本流展示，不套大面积卡片边框。
- 规划中、执行中、保存中、完成和失败均使用紧凑状态行。
- 错误摘要、取消、重试保存、返回修改等恢复动作始终直接显示，不能藏在折叠详情中。

### 8.2 图片缩略图

- 单张输出最大 `160×160px`。
- 使用 `object-contain` 保持原比例，不裁切。
- 优先使用现有缩略图缓存，避免为消息流解码完整图片。
- 点击缩略图调用现有 `setLightboxImageId`，继续使用现有 Lightbox。
- 多图任务按输出顺序横向排列并自动换行；Lightbox 继续使用完整图片列表支持前后切换。
- 运行中的流式预览沿用同一最大尺寸，完成图替换预览时不扩大布局。

### 8.3 操作行

缩略图下方始终展示现有适用动作，例如：

- 复用配置
- 编辑输出
- 高级编辑 / OpenShop
- 遮罩编辑
- 收藏 / 取消收藏
- 重试（仅适用任务）
- 删除记录

不新增“查看原图”按钮，图片本身就是查看入口；不新增重复的编辑实现。

为避免 `TaskDetailContent` 与 Agent 消息分别维护业务处理逻辑，应将现有任务动作提取为共享组件或共享动作 Hook，由任务详情、历史卡片和 Agent 结果按场景配置可见项。按钮行为、确认弹窗和禁用条件保持不变。

## 9. 执行详情

Agent 结果下方提供默认关闭的“执行详情”折叠区，容纳：

- 用户 Prompt 与工具实际使用的修订 Prompt。
- 参考图。
- 参数配置与来源信息。
- Planner 摘要、策略版本、计划 ID、执行 ID 或本地 Run ID。
- Tool 消息和流式中间预览；所有最终输出统一留在上方缩略图组，不在详情中重复。
- 原始图片链接与原始响应。

折叠区只展示详情信息，不重复顶部结果缩略图和操作行。可通过提取共享详情片段，或为 `TaskDetailContent` 增加仅详情展示的 Agent presentation 实现；完整任务详情弹窗继续保留现有完整视图。

## 10. 模板栏

- 继续复用现有 `AgentTemplateRail` 和模板应用逻辑。
- 桌面端默认收起为右侧入口栏，点击覆盖式展开。
- 桌面端选择模板后保持当前展开状态，便于连续浏览模板。
- 移动端选择模板后自动关闭抽屉并回到输入区。
- 展开模板不能改变中央消息流宽度或输入区位置。

## 11. 状态与数据流

```text
现有任务/会话 Store ─┐
Chat 流式 Session ───┼─> 模式适配层 ─> 共享消息流 ─> 文本 / 缩略图 / 操作 / 详情
Tool 执行 Store ─────┘

布局偏好 Store ───────────────> 历史栏 / 模板栏 / 移动端抽屉
```

模式适配层只生成当前渲染所需的临时 View Props，不持久化、不复制任务状态。执行命令仍由现有 Store、API 和事件订阅处理。

## 12. 组件边界

建议的职责拆分：

- `AgentWorkspace`：模式切换、双侧栏状态、桌面/移动布局和当前任务选择。
- `AgentConversationStream`：消息列表、滚动跟随、空状态和回到底部。
- `ChatAgentConversation`：把现有 Chat 会话和流式 Session 映射为共享消息结构。
- `ToolAgentConversation`：把计划、执行、本地 Run 和任务结果映射为共享消息结构。
- `AgentResultReply`：状态、文本、缩略图、错误摘要和操作行。
- `AgentExecutionDetails`：默认折叠的 Prompt、参数、计划、Run 与原始响应。
- `TaskActionRow` 或共享 Hook：复用当前任务动作与可见性规则。
- `AgentImagePreview`：继续负责缩略图缓存，并补充点击、图片列表和加载状态能力。
- `InputBar`：保留业务逻辑，增加 Agent 内嵌 presentation。

不要求文件名必须与上述建议完全一致，但实现应保持这些职责边界，避免重新形成两个大型模式组件。

## 13. 无障碍与键盘行为

- 历史和模板开关提供明确 `aria-expanded`、`aria-controls` 和可访问名称。
- Chat/Tool 切换继续使用 tab 语义和方向键导航。
- 缩略图使用按钮语义或可键盘激活的交互容器，`Enter`/`Space` 打开 Lightbox。
- `details/summary` 或等价 Disclosure 保留可键盘操作和展开状态。
- 移动端抽屉打开后约束焦点，关闭后把焦点还给触发按钮。
- 错误状态使用可读文本，不仅依赖颜色。
- 所有新布局保持现有深色模式。
- UI 动画遵循 `prefers-reduced-motion`。

## 14. 测试策略

### 14.1 单元与组件测试

至少覆盖：

- Chat 与 Tool 使用同一消息流骨架。
- Chat 多轮消息顺序和历史恢复。
- Tool 规划、确认、执行、保存、完成与失败状态在同一消息位置切换。
- 输出缩略图具有最大 `160×160px` 约束、保持比例且使用缩略图缓存。
- 点击缩略图打开现有 Lightbox，并传入完整输出列表。
- 多图换行与 Lightbox 前后切换数据。
- 现有操作行的可见性、禁用条件和回调保持一致。
- “执行详情”默认折叠，展开后显示详情且不重复结果图和操作行。
- 历史默认展开、可收起；模板默认收起、可展开。
- 桌面偏好持久化，移动端抽屉不恢复为打开状态。
- `Escape`、焦点恢复、ARIA 状态和键盘打开缩略图。
- InputBar 的 Agent 内嵌模式不影响画廊固定模式。

### 14.2 浏览器验证

在 `1920×1080`、`1366×768`、`1024×768` 和 `390×844` 视口验证：

- 中央消息流留白舒展，没有三栏挤压。
- 输入区不会遮挡最后一条消息、操作行或执行详情。
- 历史收起后对话流扩展正确。
- 模板覆盖展开不改变中央宽度。
- 长 Prompt、长 Agent 文本、多图、竖图和横图不撑破布局。
- 运行中、失败、保存重试和历史恢复状态可见且可操作。
- 深色模式和减少动画模式正常。

### 14.3 回归验证

- 执行现有前端测试和构建。
- 保持 Gateway 测试不变并确认前端修改未影响协议类型。
- 验证画廊、详情弹窗、Lightbox、OpenShop、遮罩编辑和模板应用流程。

## 15. 验收标准

实现完成必须满足：

1. Chat 与 Tool 均呈现统一、响应式的消息流。
2. 桌面历史默认展开可收起；模板默认收起可覆盖展开。
3. 结果图默认不超过 `160×160px`，不裁切，点击可打开现有 Lightbox。
4. 当前常用操作直接显示并复用原逻辑，没有新增重复入口。
5. Prompt、参数、Run、计划和原始响应默认收在“执行详情”。
6. 错误摘要和恢复动作不被折叠隐藏。
7. 输入区不遮挡内容，模板展开不压缩中央消息流。
8. 无任务数据迁移，旧历史可正常恢复。
9. 画廊和完整任务详情体验不发生非预期变化。
10. 相关测试、构建和目标视口浏览器验证通过。

## 16. 风险与控制

- **共享操作逻辑提取造成回归**：先用现有 `TaskDetailContent` 和 `TaskCard` 测试锁定动作可见性与回调，再提取共享实现。
- **InputBar 移入 Agent 中央列影响提交**：只增加 presentation 和挂载位置，不改表单状态、上传和提交路径；画廊保留旧挂载方式。
- **Chat 流式状态因重构卸载**：继续保持 Chat 模式组件挂载，并用现有 Session 合并逻辑更新最后一轮。
- **长历史和多图造成性能问题**：继续使用缩略图缓存；消息列表先保持现有规模，若实测需要再单独设计虚拟化，不纳入本次范围。
- **侧栏覆盖阻挡操作**：桌面模板只覆盖右侧可用区域并支持显式关闭；移动端使用带遮罩抽屉和焦点管理。

## 17. 回滚

本次无数据迁移和协议变更。若新布局出现阻断性问题，可通过回退 Agent 展示层提交恢复原有 `AgentWorkspace`、`LegacyAgentMainWorkspace` 和 `AgentMainWorkspace` 布局，现有任务、历史和执行数据无需处理。
